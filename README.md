## :dart: O guia para alavancar a sua carreira

> Docker é a ferramenta que virou padrão para empacotar, distribuir e rodar aplicações: praticamente toda vaga de desenvolvimento, DevOps ou dados hoje espera que você saiba criar um Dockerfile e subir um `docker compose up`. Este guia reúne roadmap, documentação oficial, cursos gratuitos e pagos, livros, canais, ferramentas, projetos práticos e um capítulo dedicado a usar IA na prática com Docker — tudo verificado e organizado para quem está subindo o primeiro container ou quer aprofundar em build multi-stage, segurança de imagens e orquestração.

## 🤖 IA na prática

Docker está no centro de como IA é construída, testada e distribuída hoje: modelos, agentes e servidores MCP costumam ser publicados como imagens, e o próprio Docker Desktop passou a trazer um assistente de IA embutido (o Gordon) e um catálogo de servidores MCP prontos para rodar em container.

**Para aprender**
- Cole um erro de build (ex.: `failed to solve: process "/bin/sh -c npm install" did not complete successfully`) e peça: *"explique a causa provável e mostre a correção linha a linha"*.
- Peça para explicar, comando por comando, um `Dockerfile` ou `compose.yaml` de um projeto open source que você não escreveu — Docker tem uma sintaxe densa e a IA já viu milhares de exemplos parecidos.
- Peça exercícios práticos: *"me dê um desafio de multi-stage build para uma aplicação Node.js, sem me dar a resposta"* — você tenta, a IA revisa.
- Use o [Gordon](https://docs.docker.com/desktop/features/gordon/), o assistente de IA embutido no Docker Desktop, para gerar e explicar Dockerfiles direto na sua máquina.

**Para trabalhar**
- Ferramentas como [GitHub Copilot](https://github.com/features/copilot) e [Claude Code](https://code.claude.com/docs/en/overview) escrevem Dockerfiles, arquivos `compose.yaml` e pipelines de CI/CD a partir de uma descrição em linguagem natural — sempre revise antes de rodar em produção.
- O [Docker Model Runner](https://docs.docker.com/ai/model-runner/) permite baixar e rodar modelos de IA localmente com comandos parecidos com os que você já usa para imagens (`docker model run`).
- O [Docker MCP Toolkit](https://docs.docker.com/ai/mcp-catalog-and-toolkit/) e o [catálogo de servidores MCP](https://hub.docker.com/catalogs/mcp) publicado no Docker Hub deixam qualquer assistente de IA (Claude, Cursor, Copilot) conectado a ferramentas reais — banco de dados, sistema de arquivos, APIs — rodando isoladas em container.
- Depois de aceitar qualquer sugestão de IA para um Dockerfile, rode um linter como o [Hadolint](https://github.com/hadolint/hadolint) e um scanner de vulnerabilidades como o [Trivy](https://github.com/aquasecurity/trivy) antes de publicar a imagem.

**Limites e boas práticas**
- IA **inventa flags e opções** de comandos do Docker CLI com frequência, principalmente para recursos recentes do BuildKit. Confira sempre na [referência oficial](https://docs.docker.com/reference/cli/docker/).
- Nunca copie para dentro de uma imagem — nem peça para uma IA gerar um `Dockerfile` com — segredos, chaves de API ou senhas embutidas com `ENV` ou `ARG`; use secrets do BuildKit ou variáveis injetadas em tempo de execução.
- Desconfie de um `Dockerfile` sugerido que rode como `root` sem necessidade, use `latest` como tag fixa em produção, ou copie `.env`/`.git` inteiros para dentro da imagem (`.dockerignore` existe por isso).
- Ao rodar um servidor MCP de terceiros em container, leia o que ele faz antes de dar acesso a credenciais reais — o isolamento do container ajuda, mas não substitui revisão.

## 🎓 Certificações

- [Certified Kubernetes Administrator (CKA)](https://training.linuxfoundation.org/certification/certified-kubernetes-administrator-cka/) — Certificação da CNCF para quem avança de Docker para operação de clusters Kubernetes — exame pago.
- [KodeKloud Engineer — trilha com certificado](https://kodekloud.com/kodekloud-engineer/) — Programa hands-on de labs práticos que emite certificado de conclusão — plano pago.
